## Why this design

The previous ECS Fargate plan needed public ingress and private data networking. An ALB, NAT gateway, RDS and ElastiCache each add idle charges; a task public IP alone has no stable HTTPS hostname. App Runner supplies an AWS HTTPS hostname and keeps one provisioned instance warm. It accepts ECR images, so the reviewed private Docker Hub image is copied to private ECR without rebuilding. It has a 120-second total HTTP request limit; the current v2 chat stream timeout is 90 seconds, but real SSE flushing must be checked in Step 16. App Runner has no separately billed ALB in this Terraform stack. [App Runner pricing](https://aws.amazon.com/apprunner/pricing/), [HTTP timeout](https://docs.aws.amazon.com/apprunner/latest/dg/develop.html), [ECR image requirement](https://docs.aws.amazon.com/apprunner/latest/dg/service-source-image.html).

The user has existing **Neon PostgreSQL and Upstash Redis** settings in the ignored local `Backend/.env`. App Runner's default outbound access reaches those services, Google, Razorpay and Bedrock without a customer NAT gateway. A Neon compute that sleeps can still cause a slow first database request, so a warm App Runner instance alone cannot guarantee every request is wait-free. Confirm Neon compute settings against the available plan before claiming this behavior. [App Runner outbound networking](https://docs.aws.amazon.com/apprunner/latest/dg/network-vpc.html).

## Delivered files and controls

- [`infra/demo`](../../infra/demo/main.tf): Terraform creates ECR, App Runner, one warm instance with a two-instance cap, ECR access and app instance roles, a GitHub OIDC deployment role, cost budget, SNS email alert, and 5xx alarm. App Runner writes application and deployment logs to CloudWatch automatically. The runtime role can read only configured secret ARNs and invoke only approved Bedrock resources. The GitHub role can mirror into one ECR repo, update one App Runner service, and read only migration settings. Terraform creates no VPC, ALB, NAT, RDS, ElastiCache, frontend bucket, EC2 server or cluster.
- [`backend-demo-deploy.yml`](../../../.github/workflows/backend-demo-deploy.yml): manual, serialized, protected `backend-demo` environment; accepts only `codex/backend-baseline` or `main`. It uses OIDC, no long-lived AWS key. The script checks successful source CI and release runs, Docker Hub digest and platform, then copies to ECR. The destination ECR digest is recorded separately because a registry copy can change the manifest digest.
- [`demo-release.sh`](../../deploy/demo-release.sh) and [`demo-update.sh`](../../deploy/demo-update.sh): `bootstrap` mirrors the image and runs the migration-only container. `deploy` also updates App Runner, waits for the deployment operation, checks readiness, and restores the prior image/configuration on failure. Database schema migrations are never automatically reversed. Terraform ignores later image changes so the release workflow owns them.
- [`backend-tests.yml`](../../../.github/workflows/backend-tests.yml): no-credential Terraform format/init/validate and mocked plan gates.

The application uses at most 10 PostgreSQL connections per instance; the two-instance cap means up to 20 app connections plus migration/admin headroom. App Runner HTTPS terminates at the managed edge. The production profile still requires `DATABASE_URL` with `sslmode=verify-full`, remote Redis with `REDIS_SSL=true` and a password, valid signing/encryption keys, exact HTTPS CORS origins, and Bedrock/v2 flags. The exact Netlify origin is a public Terraform variable, so it needs no AWS secret. Preserve the existing `ENCRYPTION_MASTER_KEY` for any existing encrypted rows and JWT keys if token continuity is required. Secret values live in AWS Secrets Manager or SSM SecureString and are injected by ARN; Terraform state holds references, not secret values. The one-off migration has a separate DDL user/password reference from the app runtime credentials. Rotation needs an App Runner redeployment. [App Runner secrets](https://docs.aws.amazon.com/apprunner/latest/dg/env-variable.html).
