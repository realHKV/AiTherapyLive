# Sydney staging design — 2026-10-27

Status: **superseded by the lower-cost [EC2 option](STAGING_SYDNEY_EC2_OPTION.md) at the user's request; no AWS resources created**. This document remains as the priced managed alternative.

## Managed alternative

Use one Amazon ECS Express Mode service for the Java backend. Express Mode supplies an AWS-owned public HTTPS URL, an Application Load Balancer (ALB), ACM certificate, Fargate task, and deployment monitoring. The resulting API base is `https://<service-name>.ecs.ap-southeast-2.on.aws/api/v1`; the service name is confirmed after creation. Netlify's HTTPS certificate only covers the frontend, so browser API calls and the Google OAuth redirect still need this backend HTTPS URL.

Use the existing Sydney default VPC and public subnets for the initial staging task. Keep the task security group restricted to traffic from the ALB on port 8080. The task uses a public IPv4 address for outbound Neon, Upstash, Google, Razorpay, and Bedrock traffic; no NAT gateway is needed. Do not treat the task's public IP as an API endpoint. ALB-to-task traffic is HTTP inside the VPC; this is acceptable only for synthetic staging. Reassess private subnets and transport encryption before real therapy content.

## Concrete settings

| Item | Staging setting |
| --- | --- |
| Service name | `aitherapy-staging` if available |
| Container image | Existing `linux/amd64` Dockerfile, published to ECR and pinned by digest |
| Task | Fargate Linux/x86_64, **0.5 vCPU, 2 GiB**, one task minimum and maximum |
| Container | Port 8080; `GET /api/v1/actuator/health/readiness` as health check |
| Load balancer | Public HTTPS 443; target HTTP 8080; idle timeout at least 120 seconds for chat streaming |
| Task role | Bedrock invocation of the approved Nova model IDs only; no long-lived AWS key in environment |
| Execution role | ECR pull and CloudWatch logs; secret retrieval scoped to staging secret ARNs |
| Secrets | Neon credentials, Upstash password, Google OAuth client secret, JWT private key, encryption key, and Razorpay **test** secrets from AWS Secrets Manager references in a custom ECS task definition; no plaintext secrets in Terraform state or checked-in files |
| Non-secret environment | `BEDROCK_REGION=ap-southeast-2`, reviewed model IDs and feature flags, `REDIS_SSL=true`, `DEV_MODE=false`, `OAUTH_TICKET_HANDOFF=true`, `SPRING_FLYWAY_ENABLED=false` for the serving task, exact Netlify HTTPS site in `CORS_ALLOWED_ORIGINS` |
| Logs | CloudWatch log group with 14-day retention; avoid message, token, and secret logging |
| Monitoring | Existing $15 budget alert plus task health, ALB 5xx, and cost checks during the run; stop/delete staging after acceptance |

The custom task definition is needed for ECS secret references and precise roles. Express Mode still owns the URL and ALB. Run the image's `migrate` mode as a one-off task from the **same image digest** before starting the service, against a disposable staging database or a verified backup. The serving task disables automatic Flyway migration so a later restart cannot change the schema unexpectedly.

## URLs and browser flow

Once AWS returns the actual service URL:

- Netlify build variable: `VITE_API_BASE_URL=https://<service-name>.ecs.ap-southeast-2.on.aws/api/v1`.
- Google authorized redirect URI: expected `https://<service-name>.ecs.ap-southeast-2.on.aws/api/v1/login/oauth2/code/google` because the app's servlet context path is `/api/v1`. Verify the `redirect_uri` generated by Spring in staging, then register that exact value in Google.
- Razorpay test webhook: `https://<service-name>.ecs.ap-southeast-2.on.aws/api/v1/payment/webhook`.
- Backend sends OAuth handoff ticket back to `https://<netlify-site>.netlify.app/oauth2/redirect`; the exact Netlify URL must lead the CORS origins list.

Spring now uses native forwarded-header handling so ALB `X-Forwarded-Proto` can produce an `https://` redirect. Verify the generated URI in staging and confirm client-supplied forwarded host values cannot alter the callback host. Netlify build and Google OAuth settings cannot be finalized until the actual AWS service and Netlify site URLs exist. Google may reject the shared `on.aws` redirect domain; if so, use an owned domain or a different login architecture rather than weakening OAuth checks.

## Gross cost estimate

Sydney public on-demand rates checked via AWS Price List API on 2026-10-26; 730 hours, one 0.5-vCPU/2-GiB x86 task, one ALB, illustrative one LCU average, and three public IPv4 addresses (two ALB, one task):

| Component | Calculation | USD/month |
| --- | ---: | ---: |
| Fargate CPU | 0.5 × $0.04856/h × 730 | $17.72 |
| Fargate memory | 2 × $0.00532/h × 730 | $7.77 |
| ALB hours | $0.0252/h × 730 | $18.40 |
| ALB usage | 1 LCU × $0.008/h × 730 | $5.84 |
| Public IPv4 | 3 × $0.005/h × 730 | $10.95 |
| **Illustrative baseline** | | **$60.68** |

This is about **$1.99 per 24-hour day** while running, before ECR storage, secrets, CloudWatch ingestion, data transfer, Bedrock tokens, taxes, and possible deployment overlap. LCU and IPv4 counts are assumptions, not a quote. AWS credit or free-plan coverage may reduce the payable amount, but this is the gross charge basis. The current **$15 budget is only an alert**; this design exceeds it. Set a short staging window and delete the service and unused supporting resources after acceptance. Do not assume a stopped task eliminates ALB charges.

## Order of work after cost approval

1. Run current PostgreSQL/Redis integration suite in a Docker-capable runner; no skipped tests. Review the resulting image and push an immutable digest to ECR.
2. Create the scoped task, execution, and infrastructure IAM roles; create staging secret references and a custom task definition. Verify the AWS credentials in use belong to account `492613852824` and Region `ap-southeast-2`.
3. Confirm staging Neon/Upstash resources and backup. Run the one-off migrator by image digest. Deploy ECS Express with min=max 1 and the readiness health check. Inspect generated ALB, security groups, public URL, and idle timeout; correct any unsafe default before traffic.
4. Set the actual Netlify API URL and exact CORS origin. Configure Google OAuth and Razorpay **test-mode** callback URLs. Use synthetic data only.
5. Run the Step 17–19 acceptance list in [RELEASE_READINESS.md](RELEASE_READINESS.md): OAuth ticket flow, auth lifecycle, FREE/PRO chat and SSE, memory, duplicate signed webhooks, restore, alarms, and cost. Record image/config/schema revisions and a rollback path before any production cutover.
